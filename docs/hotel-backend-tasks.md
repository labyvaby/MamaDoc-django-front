## 1. Сайт отеля как витрина

Ревьюер открыл `/stay/{slug}` как гость: нет адреса, телефона, фото, удобств,
условий отмены; превью ссылки в WhatsApp — «Aximo CRM». Публичный API отдаёт
только `propertyName` и у категорий `name / capacity / available / totalAmount`.

Фронт уже: поиск на завтра при открытии (название отеля сразу в шапке и во
вкладке), блок условий перед формой. Поля ниже фронт **уже читает** — пока их
нет, просто не показывает.

1. `GET /api/v2/hotel/public/{slug}/` — шапка до выбора дат (AllowAny, те же
   проверки и rate limit, что у `availability`):

   ```json
   {
     "name": "Viva — центр",
     "address": "Бишкек, ул. Токтогула 120",
     "phone": "+996 555 123 456",
     "email": "",
     "checkInTime": "14:00",
     "checkOutTime": "12:00",
     "logoUrl": "https://…/logo.png",
     "photos": ["https://…/hall.jpg"],
     "cancellationPolicy": "Бесплатно — до 3 суток до заезда…",
     "houseRules": "…"
   }
   ```

   Без персональных данных гостей. `photos` и `logoUrl` — абсолютные URL.
2. В `PublicCategory` (`availability`) добавить: `description`,
   `photos: string[]` (абсолютные URL фото номеров категории, первое —
   обложка), `amenities: string[]` (готовые подписи, не ключи каталога),
   `boardType` (`none | breakfast | half_board | full_board | all_inclusive`),
   `cancellationPolicy` (тарифа, по которому посчитана цена).
3. Превью ссылки: краулеры JS не выполняют и видят `index.html` CRM. Нужен
   серверный ответ для `/stay/{slug}` по аналогии с `/book/*`
   (`public_api/views/booking_preview.py`): `og:title` — название отеля,
   `og:description` — адрес и «Бронирование напрямую», `og:image` — первое
   фото. Плюс правило в Caddy для user-agent краулеров, как у `/book/*`.
4. По желанию: `?lang=en` для названий и описаний категорий.

**Признак:** `GET /public/{slug}/` не `404`, в категориях есть `photos`.

## 2. Заявка с сайта: уведомить сотрудников и подтвердить гостю

Заявка с сайта — бронь `hold` с `source="website"` на 30 минут. Фронт уже:
опрос `GET /reservations/?status=hold&source=website` раз в 45 с, в открытой
CRM — уведомление со звуком и «Открыть», счётчик на «Ресепшен», блок с
обратным отсчётом; после «Подтвердить» — кнопка отправить гостю подтверждение
в WhatsApp (вручную, со своего телефона). Если CRM закрыта — никто не узнает.

1. Уведомление сотрудникам вне CRM: Telegram/WhatsApp администратору смены
   (или общий чат отеля) сразу после `PublicBooking.post` — гость, даты,
   категория, сумма, «держим до HH:mm», ссылка `/reception?open={id}`
   (фронт открывает по ней карточку брони).
2. Автоподтверждение гостю: сообщение (SMS/WhatsApp/почта) «заявка принята»
   сразу и «бронь подтверждена» после `confirm/`; напоминание за день до
   заезда. Тексты можно взять с фронта (`src/dev/hotelGuestMessages.ts`).
3. Ночью за 30 минут никто не подтвердит. Вариант: настройка объекта «держать
   заявку с сайта N минут» или до утра (`holdMinutes` уже параметр
   `create_reservation`).
4. По желанию: событие по WebSocket (`hotel.reservation.created` с `source`) —
   тогда фронт перестанет опрашивать.

## 3. Ночной аудит: незаезды по расписанию

Подтверждённые брони, по которым гость не заехал, висят в «Требуют внимания»
неделями, держат номер и считаются долгом. На фронте есть ручная кнопка
«Закрыть день: незаезды (N)»: по каждой — `POST /reservations/{id}/cancel/`
с `noShow: true` и причиной «Незаезд — закрытие дня».

Нужно то же по расписанию: раз в сутки в часовом поясе объекта (например,
в 03:00) — брони `confirmed`, у которых `check_in < сегодня` и ни одна позиция
не заселена, → `no_show` тем же сервисом, что `cancel(no_show=True)` (номер
возвращается в продажу, бронь — не долг). В `logs` — «Ночной аудит». По
желанию — настройка объекта «закрывать незаезды автоматически» (вкл/выкл).

## 4. «Проживают» и порции кухни без незаездов и ранних выездов

Сейчас считаются проживающими все, у кого даты брони покрывают день:

- `dashboard.staying` — `items.filter(check_in__lt=on_date, check_out__gt=on_date)`
  (`selectors.py`, `OccupancySnapshot`) — без `stay_status`;
- кухня, `occupied_guests` — подтверждённые позиции с
  `check_in <= on_date < check_out`, тоже без `stay_status`.

Повар готовит порции на гостей, которые не приехали или уже уехали: на тесте
03.10 кухня считала 3 гостя при 0 проживающих — 2 незаезда и 1 ранний выезд.

Правило, по которому считает фронт (`src/dev/hotelInHouse.ts`), одно на все
экраны: проживает, если позиция `checked_in`; или `expected` и заезд сегодня
(ещё может приехать). `expected` с заездом в прошлом — незаезд; `checked_out` —
уже не проживает. Если на сервере то же правило — фронт перестанет
пересчитывать сам.

## 5. Паспорт гостя в брони без пересоздания гостей

Паспорт вносится при заселении, а не при брони. Чтобы дописать номер документа
гостю уже созданной брони, фронт шлёт `PATCH` позиции с полным списком
`guests`, а `update_reservation_item` делает `item.guests.all().delete()` и
создаёт гостей заново: теряются фото документа и связи. Поэтому, если у гостя
есть фото документа, фронт править не даёт и просит открыть карточку гостя.

Нужно: `PATCH /reservations/{id}/items/{itemId}/guests/{guestId}/` — правка
одного гостя позиции (документ, гражданство, тип гостя) без пересоздания
остальных; с `version` брони и строкой в `logs`.

## 6. Условия отмены и предоплаты как настройки

Сейчас это свободный текст в «Правилах проживания». Нужны поля объекта (или
тарифа): «бесплатная отмена до N суток до заезда», «штраф — первая ночь / N % /
сумма», «предоплата N % в течение N часов». Тогда сайт (п. 1), сообщение гостю
(п. 2) и подтверждение брони покажут одно и то же, а фронт сможет посчитать
штраф при отмене.

## 7. Распознавание без согласия → `400 CONSENT_REQUIRED`

Хвост прошлого §15. Фронт с этой версии шлёт в `POST /guests/scan-document/`
поле формы `consent=true` (фото и так уходит только после галочки согласия).
Сейчас лишнее поле сервер молча принимает — проверено 03.10.

Можно включать проверку: без `consent=true` → `400`, код `CONSENT_REQUIRED`.
Включать после выката этой версии фронта на прод — старый фронт поле не шлёт.

## 8. Стенд: распознавание паспорта упирается в квоту Gemini

Не код. По разбору бэкенда: на тесте ключ бесплатного тарифа — Google отвечает
`429 quota` и `503 high demand`, поэтому руководитель не видит, как форма
заполняется по фото. Нужен ключ платного тарифа; по желанию — зафиксировать
модель (`GUEST_DOCUMENT_RECOGNITION_MODEL` вместо `-latest`) и поднять
`GUEST_DOCUMENT_RECOGNITION_TIMEOUT`.
