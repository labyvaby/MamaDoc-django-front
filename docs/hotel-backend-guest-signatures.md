# Отель: подпись гостя на планшете — подписанные документы брони

08.10.2026 · задача #4743 · бэкенд сверен с `origin/test` = `0db5280b`

## Зачем

При заселении гость подписывает регистрационную карту: правила проживания, ответственность за
вещи и ущерб, штраф 2500 сом за курение, «Подписывая этот документ, я подтверждаю…». Сейчас
карту печатают из карточки брони и гость подписывает её ручкой. Так же на бумаге подписывается
согласие на обработку персональных данных. В системе от подписи ничего не остаётся.

Нужно, чтобы:

1. Ресепшен нажимал в карточке брони «Подписать на планшете».
2. На планшете у стойки появлялся документ.
3. Гость расписывался стилусом.
4. Подписанный документ хранился у брони: точный текст, который гость видел, его версия,
   подпись, время, кто отправил на подпись, с какого устройства и проверочная сумма. Документ
   неизменяем: его можно аннулировать с причиной, но нельзя удалить или поправить.

Фронт начнём после ответа по этому документу. Ниже — предлагаемая схема. Если что-то удобнее
сделать иначе, напиши: фронт подстроится.

## Что уже есть и на что опираться

- **Согласие на ПДн.** Редакции текста лежат в `ConsentTemplateVersion` (`properties/{id}/consent-template/`).
  Отметка согласия у брони — `data_consent`, `_version`, `_at`, `_by`; у профиля гостя —
  `set_guest_data_consent`.
- **Защищённые файлы.** `server/common/attachments.py`: `attachment_storage_path`,
  `attachment_response`, `store_attachment_files`. Это то же, на чём `ClientAttachment` отдаёт
  файлы только через API: `/media/` публичный, класть туда подпись нельзя. Фото паспорта
  (`document_photo`) сейчас отдаются как `field.url` из `/media/` — для подписи так не надо.
- **Подсказки в сокет.** `realtime.broadcast.broadcast_change_on_commit`, как `hotel.reservation`
  в `hotel/events.py`.
- **Pillow есть.** Им можно проверить, что PNG настоящий и подпись не пустая.
- **Библиотеки для PDF нет.** Поэтому сервер хранит текст и подпись, а печатную форму («Печать»,
  PDF) фронт собирает из сохранённого текста. Так уже печатаются все документы брони
  (`hotelPrintDocs.ts`). Если нужен архивный PDF на сервере — это отдельное решение и отдельная
  библиотека, в этой задаче не нужно.
- **Текст регистрационной карты собирает фронт.** Это константы правил на EN/RU, правила объекта
  `houseRules`, даты, номер, ФИО и оплата. Поэтому текст присылает фронт при создании запроса, а
  сервер хранит его как снимок: планшет показывает ровно сохранённое, подпись привязывается к
  нему. Текст согласия — из `ConsentTemplateVersion`, его фронт присылает так же, с `contentVersion`.

## Модель

Одна модель на весь жизненный путь: запрос на подпись → подписан. Например, `GuestSignature`.

| Поле | Что |
|---|---|
| `organization`, `property`, `reservation`, `item` (null) | `item` — номер брони. Регистрационная карта — на номер, согласие — на бронь или гостя. |
| `guest` → `ReservationGuest` (null) | Чей документ. Пусто — основной гость или вся бронь. |
| `document_type` | `registration_card`, `data_consent`. Список можно расширять: акт ущерба, договор юрлица… |
| `status` | `pending` → `signed` или `cancelled`. Просроченный `pending` отдаётся как `expired`: можно считать при чтении, хранить не обязательно. |
| `title`, `body`, `fields` | Снимок текста. `body` — абзацы через пустую строку, как у согласия, до 20 000 символов. `fields` — JSON `[{label, value}]`, до 30 штук: шапка карты (даты, номер, ФИО, оплачено). |
| `content_version` | Например, `"1.3"` у согласия, у карты — что пришлёт фронт. Строка до 32 символов. |
| `content_sha256` | SHA-256 канонического JSON `{documentType, title, body, fields, contentVersion, reservationId, itemId, guestId, signerName}`. Сортированные ключи, UTF-8. Считается при создании. |
| `signer_name` | ФИО подписывающего, как напечатано в документе. Задаёт ресепшен. |
| `created_by`, `created_at`, `expires_at` | Кто отправил на подпись. Срок жизни запроса по умолчанию 30 минут. |
| `signature` | `FileField`: PNG подписи, путь через `attachment_storage_path`, отдаётся только через API. |
| `signature_sha256`, `document_sha256` | `document_sha256 = sha256(content_sha256 + signature_sha256 + signed_at ISO)` — одна сумма на весь подписанный документ, фронт печатает её внизу. |
| `signed_at`, `signed_by` | `signed_by` — пользователь, под которым вошёл планшет. |
| `signed_user_agent`, `signed_ip` | Чем и откуда подписали — для разбора споров. IP — если считаешь допустимым хранить. |
| `cancelled_at`, `cancelled_by` | Отмена запроса до подписи. |
| `voided_at`, `voided_by`, `void_reason` | Аннулирование подписанного. Сама подпись и текст остаются. |

Правила:

- **Подписанный документ не меняется и не удаляется.** `reservation` — `on_delete=PROTECT`.
- **Новый запрос того же `document_type` на тот же `item`/`guest` отменяет прежний `pending`.**
  Ресепшен нажал «Отправить ещё раз» — на планшете не должно висеть два одинаковых.
- **Подписание согласия (`data_consent`) ставит согласие брони** (`data_consent=True`, версия —
  `content_version`, время, сотрудник), так же, как сейчас галочка. Если указан гость — ещё и
  `set_guest_data_consent`.
- **В историю брони (`_log`) пишется:** `document_sent`, `document_signed`, `document_cancelled`,
  `document_voided` — с типом документа и, у аннулирования, причиной.

Планшет — отдельная учётка с ролью «Планшет подписи». Гость держит его в руках, поэтому выйти
в шахматку, кассу или к паспортам с него нельзя. Он видит только ожидающие документы своего
объекта. Учётке нужен доступ к `/ws/changes/` — проверь, что консьюмер пускает пользователя с
одним этим правом.

## Эндпоинты

Все — под `/api/v2/hotel/`, ошибки в обычном конверте. Права к каждому — в таблице выше.

### Ресепшен

```http
POST /reservations/{id}/signatures/
{
  "documentType": "registration_card",
  "itemId": 51,
  "guestId": null,
  "signerName": "Аматов Мухаммед",
  "title": "REGISTRATION CARD / РЕГИСТРАЦИОННАЯ КАРТА",
  "fields": [
    { "label": "Arrival / Заезд", "value": "06.10.2026 (14:00)" },
    { "label": "Room / Номер", "value": "112" }
  ],
  "body": "Attention: On the territory of the Viva Hotel…\n\nВнимание: На территории отеля Viva…",
  "contentVersion": "rc-2026-10-08"
}
→ 201 SignaturePayload (status "pending")
```

- Бронь отменена, незаезд или истекла → `409 INVALID_TRANSITION`.
- `itemId` или `guestId` не из этой брони → `400`.
- Пустой `body`, длины сверх лимитов → `400`.
- Подсказка в сокет: `entity='hotel.signature'`, `action='sent'`,
  `meta={propertyId, reservationId, status}`.

```http
GET  /reservations/{id}/signatures/             → [SignaturePayload] — все, свежие сверху
POST /signatures/{sid}/cancel/                  → SignaturePayload; не pending → 409 INVALID_TRANSITION
POST /signatures/{sid}/void/  { "reason": "…" }  → SignaturePayload; не signed → 409; пустая причина → 400
```

### Планшет

```http
GET /signatures/pending/?propertyId=7    → [SignaturePayload] — pending, не просроченные, старые первыми
GET /signatures/{sid}/                   → SignaturePayload с полным текстом

POST /signatures/{sid}/sign/             multipart: signature = PNG
→ 200 SignaturePayload (status "signed")
```

Проверки при подписании:

| Ответ | Когда |
|---|---|
| `409 SIGNATURE_NOT_PENDING` | Уже подписан или отменён. |
| `409 SIGNATURE_EXPIRED` | Просрочен. |
| `400` | Не PNG, больше 512 КБ или сторона больше 3000 px. |
| `400 SIGNATURE_EMPTY` | Пустая картинка: «чернил» меньше порога, например 150 непрозрачных и не белых пикселей. Гость коснулся экрана точкой. |

После подписи — подсказка `entity='hotel.signature'`, `action='signed'`: карточка брони на
ресепшене обновится сама.

### Картинка подписи

```http
GET /signatures/{sid}/signature/    → image/png
```

`Cache-Control: private, no-store`, через `attachment_response`. Только для `status="signed"`.

## Как этим будет пользоваться фронт

Для понимания, менять ничего не нужно:

1. **Карточка брони.** «Подписать на планшете» → выбрать документ → фронт собирает текст (как для
   печати) → `POST …/signatures/`. Карточка показывает «Ждёт подписи на планшете…» и обновляется
   по подсказке `hotel.signature`.
2. **Планшет.** Отдельная страница: экран «Ждём документ» → по подсказке или раз в 10 секунд
   `GET signatures/pending/` → документ на весь экран → поле подписи (холст, стилус или палец) →
   «Подписать» → `POST …/sign/` → «Спасибо» → снова ожидание.
3. **Вкладка «Документы» брони.** Подписанные документы с датой и подписью: «Печать» и PDF
   собираются из `title`/`fields`/`body`, картинки подписи и `documentSha256` внизу листа. Плюс
   «Аннулировать».

## Тесты, которые хотелось бы видеть

- **Полный путь:** создание → `pending` на планшете → подпись → `signed`.
  - Совпадают `content_sha256` и `document_sha256`.
  - В истории брони есть записи.
- **Повторная отправка** того же документа отменяет прежний `pending`.
- **Ошибки подписи:**
  - просроченный запрос → `409 SIGNATURE_EXPIRED`;
  - повторная подпись → `409 SIGNATURE_NOT_PENDING`;
  - пустая подпись → `400 SIGNATURE_EMPTY`;
  - не PNG → `400`.
- **Согласие:** подпись `data_consent` ставит согласие брони с версией.
- **Права:**
  - роль только с `hotel.signatures.collect` видит `pending/` и подписывает, но не видит брони
    (`403` на `reservations/`) и не создаёт запросы;
  - без `hotel.guests.documents` — `403` на картинку подписи;
  - чужая организация или филиал — `404`.
- **Аннулирование:** подписанный документ не удаляется, текст и подпись остаются, у
  неподписанного — `409`.
